Change detection -- механизм обнаружения изменений
Визуализатор: https://www.change-detection.guide/

В Agnular есть две стратегии обнаружения изменений:
1. Default -- используется по умолчанию;
2. OnPush -- стратегию, которую необходимо использовать всегда для улучшения перфоманса.

>[!tip] 
>*cdr.dettach()* -- отключит обнаружение изменений для компонента
>
>*cdr.reattach()* -- включит обнаружение изменений обратно для компонента
>
>Это может быть необходимо для того, чтобы на время тяжелых и долгих вычислений отключить перериросовки, чтобы не нагружать приложение

OnPush запустит обнаружение изменений (и перерисовку):
 - на пользовательские события (например click), *которые слушаются* (т.е. для них навешен обработчик событий). Например (mouseenter)="null" запустит обнаружение изменений;
 - на изменение Input параметров, т.е. когда Input стал указывать *на новую ссылку*;
 - cdr.detectChanges() -- для себя и вложенных Default компонентов;
 - cdr.markForCheck() -- обнаружит изменения на следующем цикле перерисовки.
В остальных случаях, changeDetection не выполнится. (лучше посмотреть в визуализа торе, в чем отличие от Default)

>[!tip] Внутри | asynс pipe находится встроенный cdr.markForCheck()
>Поэтому по возможности следует использовать его. (А не стандартный способ с записью в переменную)

>[!tip] *ngDoCheck* можно использовать для настройки кастомной логики обнаружения изменений
>*ngDoCheck* выполняется, когда *должен* произойти ChangeDetection.
>
>Это можно использовать например в канвас, чтобы триггерить перерисовку компонента, только когда это действительно необходимо

## Как устроено обнаружение изменений в Angular
Change Detection состоит из двух частей:
1. Когда вызывать проверку?
2. Проверить, измененились ли значения, нужна ли перерисовка.

### Когда вызывать проверку?
Проверка вызывается тогда, когда счетчик асинхронных операций равен нулю. Т.е. все асинхронные операции выполнились. 
- есть зоны, которые патчат все асинхронные события и изменяют счетчик (+1 в начале события и -1 при выполнении);
- Когда счетчик равен нулю -- значит зона стабильна;
- Когда зона стабильна -- значит можно запускать changeDetection проверку.

>[!warning] От зоны хотят отказаться со времен 5-го Ангулара, но пока все еще не могут это до конца сделать

>[!tip] Зону можно отключить
>Зону можно отключить, если у нас есть какие то сложные анимации или что то еще, что должно постоянно триггерить перерисовку. Стоит использовать, когда нужно подключить тяжеловесные библиотеки. Например карты.
>```ts
>private ngZone = inject(NgZone);
>ngZone.runOutsideAngular(() => {});
>```

Каждый этап проверки изменений -- это подъем до корня приложения и спуск обратно к элементу.
При подъеме к корню, все элементы помечаются как *dirty*, а при спуске от корня к элементу проверяются все *dirty* элементы
