### **Фаза 1: Ядро Angular — Быстрое погружение (2-3 недели)**

Не перечитывай всю документацию. Сфокусируйся на ключевых концепциях, **сразу применяя их в пет-проекте**.

**Тема 1: Современные компоненты и шаблоны (Практика: перепиши старый компонент)**

- **Что изучить:** Standalone Components (это критически важно!). Отказ от NgModules для новых компонентов. `@Input()`, `@Output()`, жизненный цикл (OnInit, OnDestroy, OnChanges).
- **Практика:** Создай несколько standalone-компонентов: умный header, таблицу с данными, модальное окно. Свяжи их через `@Input()`/`@Output()`. Используй современный синтаксис control flow (`@if`, `@for`, `@switch`) вместо `*ngIf`, `*ngFor`. **Выбрось из головы старый синтаксис.**

**Тема 2: Управление состоянием и реактивность (Практика: реализуй состояние небольшого приложения)**

- **Что изучить:** Signals (`signal()`, `computed()`, `effect()`). Это новая, фундаментальная абстракция. Пойми разницу между RxJS Observables и Signals. Для начала используй Signals для локального состояния компонента.
- **Практика:** Создай простой «корзину товаров» или «todo-приложение» на Signals. Реализуй добавление, удаление, вычисление общей суммы/количества через `computed()`.

**Тема 3: Работа с данными и HTTP (Практика: подключись к публичному API)**

- **Что изучить:** Новый `HttpClient` (он стабилен, но убедись, что знаешь интерсепторы, прогресс загрузки). `inject()` вместо конструктора для DI — везде используй это. Менеджер состояния: для сеньор-уровня нужно понимать выбор. Изучи **NgRx ComponentStore** (идеален для фич) и **Signals + Services** как легковесную альтернативу. RxJS — освежи ключевые операторы (`map`, `switchMap`, `catchError`, `takeUntilDestroyed`).
- **Практика:**
    1. Напиши сервис с `HttpClient` и `inject()` для загрузки данных с [JSONPlaceholder](https://jsonplaceholder.typicode.com/).
    2. Создай интерсептор для добавления заголовков (например, имитация авторизации) и логирования.
    3. Реализуй фичу (например, список постов) используя ComponentStore или сервис на Signals.

**Тема 4: Роутинг и ленивая загрузка (Практика: настрой многостраничное приложение)**

- **Что изучить:** Standalone-роутинг. `provideRouter`, ленивая загрузка через `loadComponent` или `loadChildren`. Защитники роутов (Guards) — теперь это чаще функции.
- **Практика:** Организуй в пет-проекте структуру: Главная, Лента постов (лениво загружаемая), Детальная страница поста, Профиль (требует «авторизации» через guard-функцию). Используй standalone-компоненты для всего.

### **Фаза 2: Инструменты и Экосистема Сеньора (3-4 недели)**

Здесь ты доказываешь, что не просто кодер, а инженер.

**Тема 5: Производительность и Бандлинг (Практика: анализируй и оптимизируй)**

- **Что изучить:** Angular DevTools (Profiler). Ленивая загрузка, `defer` view (новая фишка в шаблонах). Разделение vendor-бандлов. Инструменты: `source-map-explorer`, `webpack-bundle-analyzer` (хотя Angular CLI теперь использует esbuild).
- **Практика:**
    1. Собери пет-проект с `ng build`. Проанализируй бандл.
    2. Намеренно создай «тяжелый» компонент и вынеси его в лениво загружаемый бандл с помощью `loadComponent` или `@defer`.
    3. Используй `takeUntilDestroyed` или `DestroyRef` для отписки от потоков.

**Тема 6: Тестирование (Практика: покрой ключевые части тестами)**

- **Что изучить:** Jest (современная альтернатива Karma/Jasmine) — многие проекты переходят на него. `TestBed` для интеграционных, `ComponentHarness` для устойчивых unit-тестов.
- **Практика:** Напиши:
    1. Unit-тест для сервиса с `HttpClientTestingModule`.
    2. Компонентный тест с `TestBed` для твоего умного компонента.
    3. Интеграционный тест для страницы, используя харнессы.

**Тема 7: CI/CD и Процессы (Практика: настрой «как в продакшене»)**

- **Что изучить:** Конфигурации окружений (`environment.ts`). Скрипты сборки для dev/prod. Линтинг: ESLint с правилами для Angular. Prettier. Husky для pre-commit хуков.
- **Практика:** Настрой в пет-проекте:
    1. ESLint и Prettier, чтобы они работали вместе.
    2. Husky, который перед коммитом запускает линтинг и unit-тесты.
    3. Две конфигурации сборки: для разработки и продакшена (с минификацией и без source maps).

### **Фаза 3: Восстановление сеньор-скиллов и подготовка к собесам (2 недели)**

- **Практика: Итоговый проект.** Выбери идею уровня «админ-панель для управления контентом» или «агрегатор криптовалют». Реализуй ее с нуля, используя ВСЁ вышеперечисленное: standalone, signals, routing, state management (выбери один подход), HTTP, интерсепторы, тесты, линтинг. Выложи на GitHub. Это твое портфолио.
- **Архитектура и паттерны:** Освежи: Smart/Dumb components, Facade pattern для управления сложной логикой, принципы DRY, KISS, SOLID (особенно Single Responsibility).
- **Soft Skills:** Будь готов объяснить, **почему** ты выбрал Signals, а не RxJS для конкретного случая. Объясни trade-offs между разными подходами к состоянию. Говори о производительности, поддерживаемости, качестве кода.
- **Актуальность:** Пробегись по блогам ([Angular.io](http://angular.io/), Medium, [dev.to](http://dev.to/)), посмотри последние видео с Angular Nation, AngularAddicts. Узнай, что сейчас в тренде (SSR с Angular Universal, hydration).
